# Internationalization

Text domain: **`laao-advertiser-portal`**. Catalogs in `languages/`.

Every user-facing string is translatable — forms, validation messages, statuses, notifications, emails, admin screens, accessibility labels, and error text. A hard-coded string in an error path is the one a translator never sees, because nobody demos the failure case.

## The plugin `.mo` naming trap

**Plugins and themes name compiled catalogs differently, and porting the theme's script here breaks translation silently.**

The LAAO theme's `bin/i18n/compile.sh` renames `laao-<locale>.mo` → `<locale>.mo`. That is correct *for a theme whose domain path is inside its own directory*, because `_load_textdomain_just_in_time()` special-cases the template and stylesheet directories and looks for the unprefixed name.

**A plugin is not that case.** `load_plugin_textdomain()` and the JIT loader both look for `laao-advertiser-portal-<locale>.mo`. Renaming produces a file WordPress will never find, and the failure mode is that the site simply renders English — no error, no warning, nothing in the log.

So: `compile.sh` here keeps the prefixed name. **The rename step is deleted, not ported.** This paragraph exists because the theme's script is otherwise an excellent thing to copy, and the one line that must change is the one that looks most like boilerplate.

## Scripts

| Command | Does |
|---|---|
| `pnpm i18n:pot` | `wp i18n make-pot` → `languages/laao-advertiser-portal.pot` |
| `pnpm i18n:sync` | Merge the POT into every locale `.po` |
| `pnpm i18n:compile` | `.po` → `.mo`, plus `make-json` for JS catalogs |
| `pnpm i18n:status` | Per-locale coverage |
| `pnpm i18n:check` | The CI gate — drift, validity, translator comments |
| `pnpm i18n:locale <code>` | Scaffold a new locale |

## The drift gate

`bin/i18n/check.sh` regenerates the POT to a temporary file, normalizes both copies by stripping volatile headers (`POT-Creation-Date`, `Project-Id-Version`), and diffs. A new translatable string committed without regenerating the POT fails CI with the diff attached.

Normalization matters: without it, every run differs by a timestamp and the gate is useless noise that gets disabled within a week.

## PO validation runs on the host

`bin/i18n/validate-po.sh` runs `msgfmt -c` on each catalog **on the host machine**, not inside the wp-env container — that container is Alpine-based and has no gettext.

**A missing `msgfmt` is a hard failure, never a silent skip.** The theme's equivalent carries a comment about a real incident where `wp i18n make-mo` silently accepted broken catalogs for months. `make-mo` is lenient; `msgfmt -c` is not. Skipping the strict check when the tool is absent means the check is only running where it was never going to fail.

`bin/ci/i18n.sh` splits accordingly: extraction inside the container, validation on the host.

## Translator comments

Any string containing a placeholder needs a preceding `/* translators: */` comment naming what each placeholder is:

```php
/* translators: 1: uploaded dimensions, e.g. 1200 × 400. 2: required dimensions. */
sprintf( __( 'Uploaded: %1$s. Required: %2$s.', 'laao-advertiser-portal' ), $got, $want )
```

`bin/i18n/lint-translators.sh` fails the build on a placeholder string without one. Without the comment a translator sees `%1$s` and `%2$s` with no way to know which is which, and in a language that reorders the clause they have to guess.

## JavaScript strings, and the script-module gap

**`wp_set_script_translations()` does not work for script modules.** The Script Modules API — which the Interactivity API is built on — has no translation mechanism in WordPress today. This is a core gap, not something we can work around at the call site.

So **every user-facing string in an Interactivity store is hydrated server-side** through `wp_interactivity_state()`, already translated by PHP:

```php
wp_interactivity_state( 'laao-advertiser-portal/upload', array(
    'i18n' => array(
        'uploading' => __( 'Uploading…', 'laao-advertiser-portal' ),
        'failed'    => __( 'Upload failed. Try again.', 'laao-advertiser-portal' ),
    ),
) );
```

The store reads `state.i18n.uploading`. No string literals in TypeScript that a user will ever read.

Classic (non-module) scripts still use `wp_set_script_translations()` normally, and `make-json` produces their catalogs. Recorded in [known-issues.md](known-issues.md) so that if core closes the gap, someone knows there is a workaround to remove.

## Release

`bin/release/verify-package.sh` asserts that **every committed `.po` has a compiled `.mo` in the ZIP.** Forgetting `pnpm i18n:compile` before a release is otherwise invisible — the site just renders English, and the first report comes from a user weeks later.
