# Internationalization

Text domain: **`aggressive-ads`**. Catalogs in `languages/`.

Every user-facing string is translatable — forms, validation messages, statuses, notifications, emails, admin screens, accessibility labels, and error text. A hard-coded string in an error path is the one a translator never sees, because nobody demos the failure case.

## The plugin `.mo` naming trap

**Plugins and themes name compiled catalogs differently, and porting the theme's script here breaks translation silently.**

The LAAO theme's `bin/i18n/compile.sh` renames `laao-<locale>.mo` → `<locale>.mo`. That is correct *for a theme whose domain path is inside its own directory*, because `_load_textdomain_just_in_time()` special-cases the template and stylesheet directories and looks for the unprefixed name.

**A plugin is not that case.** `load_plugin_textdomain()` and the JIT loader both look for `aggressive-ads-<locale>.mo`. Renaming produces a file WordPress will never find, and the failure mode is that the site simply renders English — no error, no warning, nothing in the log.

So: `compile.sh` here keeps the prefixed name. **The rename step is deleted, not ported.** This paragraph exists because the theme's script is otherwise an excellent thing to copy, and the one line that must change is the one that looks most like boilerplate.

## The second silent failure: registering the directory

The naming trap above is only half of it, and this half was live in this plugin
until the catalogs were set up.

**Just-in-time loading never searches a plugin's own folder.**
`WP_Textdomain_Registry::get_paths_for_domain()` returns exactly three
locations: `WP_LANG_DIR/plugins`, `WP_LANG_DIR/themes`, and a custom path that
is only ever populated by `load_plugin_textdomain()` or
`load_theme_textdomain()`. This plugin called neither. It shipped `Domain Path:
/languages` in its header, which is metadata for translate.wordpress.org and
nothing else at runtime.

So every catalog placed in `languages/` would have been ignored, and a site
would have been translated only if somebody had installed a language pack into
`wp-content/languages/plugins/`. `Plugin::load_translations()` now makes the
call, on `init` — earlier is a `_doing_it_wrong` notice since WordPress 6.7,
because the locale is not settled until then.

**Both failures are invisible from every signal except the rendered string.**
`load_plugin_textdomain()` returns `true` whether or not it found a catalog.
The POT can be current, the `.po` valid, the `.mo` compiled and the placeholders
perfect while the whole site renders English.

`tests/php/Integration/TranslationLoadingTest.php` therefore asserts on `__()`
output. It writes a small binary `.mo` by hand rather than shelling out to
`msgfmt`, because this suite runs with `failOnSkipped` and a test that skips
where gettext is missing is a test that stops running exactly where nobody is
watching. Deleting the `load_plugin_textdomain()` call fails it; renaming to the
theme's unprefixed convention fails it too.

One constraint that shaped it: WordPress caches loaded catalogs per request in
`WP_Translation_Controller`, and `WP_UnitTestCase` does not reset that. Each
test uses its own locale, and the fallback-to-English assertion lives inside the
first test rather than in a third one, because a third load of the same domain
in one process does not take.

## Machine translation

`pnpm i18n:translate` fills empty and fuzzy entries: DeepL when
`DEEPL_AUTH_KEY` is set, MyMemory otherwise. Every filled entry is flagged
`aggr-mt` with a comment naming the provider, and MT never runs in `build` or in
the release job — the review gate is a pull request, opened by
`.github/workflows/i18n-translate.yml`.

**That workflow is started by hand, and used to run on every POT change.** What
the automatic trigger produced, twice, was a draft nobody could merge. DeepL
answered `456 Quota exceeded`, every string fell through to MyMemory, and the
German came back roughly a third defective — an ad creative rendered as a
shopping cart (*Warenkorb*), screen widths as sieve widths (*Siebbreiten*),
creatives as creative people (*Kreative*), and one string switching from *Sie*
to *du*. The second draft was reviewed and closed; the first had been sitting on
the draft branch being restored into later runs as though it were finished work.

A workflow that manufactures review work which always ends in "close" is worse
than one nobody starts. Run it deliberately, when the preferred provider is
known to be answering.

**The pull request now says which engine wrote it, before anything else.** Both
of those drafts came from `mymemory-fallback` and the only trace was a `via` tag
inside a PO comment; the pull request named no engine, and the job was red for
an unrelated reason, so even the failure pointed elsewhere. `providerMix()`
counts what actually answered across every locale and puts a warning block at
the top of the body when any of it came from a substitute. The body is rewritten
on every run, because it used to be written once at creation — so a later run
that degraded left the first run's claims standing over its own output.

Placeholders and a short do-not-translate list are protected before the request
and restored after. `bin/i18n/lint-placeholders.mjs` then re-checks parity in
`i18n:check`, because `msgfmt -c` only rejects a printf mismatch on entries
gettext flagged `php-format` and knows nothing about brace tokens.

### A string the machine keeps getting wrong is skipped, not fatal

`placeholdersIntact()` in `bin/i18n/po.mjs` is the single definition of the
rule, and it compares **both directions**. A translation that invents a
placeholder is as broken as one that drops it: a machine translator answers out
of a translation memory full of other people's strings, so "All campaigns" came
back as German carrying a `%d` borrowed from a neighbouring "%d campaigns", and
`%d` in a string PHP passes no argument to is a broken page.

That function used to return early when the source had no placeholders, so it
could only ever catch a *dropped* token, while `lint-placeholders.mjs` restated
the rule and compared both ways. One rule, two definitions, the upstream one
weaker — so the drafting workflow reliably wrote a catalog its own validator
refused, and every push to master failed the lane. The lint now calls the
function instead of restating it, and a test asserts the two agree over a table
of cases so they cannot drift apart again.

When a translation fails that check the string is **refused**: left empty or
fuzzy, named on stdout, and picked up again by the next run. It does not stop
the locale and does not fail the job. Refusing one string and stopping the
locale used to be the same code path, and because validation runs before the
draft branch is written, one string the provider kept mangling threw away the
other thousand translations on every run — and the next run regenerated it.
`judgeRun()` therefore subtracts refusals from what it calls unfinished; a
string nothing *tried* to translate still fails the run.

Because a refusal is not a failure, the run stays green — so refused strings are
also emitted as `::warning::` annotations on the workflow run, not only printed
to a log nobody opens. Without that, a string the provider mangles every time
would sit untranslated behind a green lane forever, and the draft pull request's
body is written once and never mentions it. The annotation escapes `%` before
the newline escapes, because a refused string almost always contains a literal
`%s` or `%d` — that is what it was refused for.

Refusals are told apart from a quota stop by a tag on the error
(`MT_REFUSED`), not by matching the message. The message quotes the offending
source so a human can see which string broke, and `"Limit to one advertiser"`
is a real string here — matching `/LIMIT/i` across it read a bad translation as
an exhausted quota and abandoned the rest of the locale, then reported "the
provider stopped the run" about a provider that was answering fine.

### A fuzzy flag is a review state, and only the run that fills an entry may clear it

`serializeEntry()` in `translate.mjs` used to clear `fuzzy` and stamp `aggr-mt`
on every entry it wrote — which is the whole catalog, not the handful the run
translated. Both halves were destructive, and the first is how the third
failing string reached the lint.

`msgmerge` fuzzy-matched a newly added "That delivery policy cannot be used:
`%s`" onto the older translation of the same sentence without the `%s`, and
marked it fuzzy. That is correct, and is exactly what fuzzy is for. The next
write then silently un-marked it, so a draft was published as a finished
translation, the lint stopped skipping it, and the job failed on a placeholder
the machine had never touched. **A `fuzzy` flag is gettext's record that a
string needs a human**; clearing it in a serializer throws that record away for
the entire catalog every time any one string is translated.

Stamping `aggr-mt` on everything was the same mistake pointed at provenance:
reviewed human translations were relabelled as machine output, and
`resume-progress.mjs` keys on that flag to decide what is a machine draft it
may restore over. Flags are now written exactly as they stand; the translation
loop already sets both on the entries it actually fills.

As a backstop, a machine-written entry whose placeholders do not match is
demoted to fuzzy just before the file is written, so the catalog a run produces
always passes the validation that runs next whatever wrote its entries. Human
translations are never swept — a broken one is left to fail the lint loudly,
because quietly flagging somebody's work fuzzy hides a problem only they can
fix.

The validation gate in the workflow is unchanged and stays a hard failure:
machine output with mismatched placeholders must never reach a pull request
looking reviewed. What changed is that such output is no longer written to a
catalog in the first place.

### An echo is not a translation

MyMemory returns the query unchanged when it cannot translate a string.
`translateMyMemory()` used to return that echo as the translation, so the run
wrote English into the German catalog, flagged it `aggr-mt`, cleared its fuzzy
mark and counted it among the strings it had filled. The first German draft to
reach a pull request carried eleven, including **"None"** and **"Singapore
dollar"** presented as finished German.

An echo is refused now. The entry stays empty, gettext falls back to the source
string — which is exactly what the echo would have displayed — and the string is
named for a human instead of hidden among the finished ones. Some strings really
are identical in both languages ("Euro", "Code", "CTR"), and nothing mechanical
can tell those from a provider giving up. That is the point: a person can, and
now gets asked.

### The glossary earned its first entries

`LOCALE_GLOSSARY` in `providers.mjs` was deliberately empty, to be filled from mistakes MT actually
made on *this* catalog rather than someone else's. Reviewing that same draft
supplied the first four, all German:

| MT wrote | should be | why |
|---|---|---|
| Konvertierung(en) | Conversion(s) | the ad industry keeps the loanword; *Konvertierung* is converting a file — and MT used both in adjacent strings |
| Fenster Namensnennung | Attributionsfenster | *Namensnennung* is attribution in the give-credit sense, the word in the German Creative Commons licences |
| Befundungsschlüssel | Berichtsschlüssel | *Befundung* is a radiologist writing up a scan |

Longest keys first, because the pass is a plain substring replace:
`Konvertierungen` has to precede `Konvertierung` or it becomes *Conversionen*.
There is a test for that ordering, and it fails when the two are swapped.

**One correction was deliberately left out.** MT rendered an API credential as
*Ausweis*, an identity card. It is wrong, but *Ausweis* is masculine where
*Anmeldedaten* is plural, so swapping the noun alone turns "Dieser Ausweis" into
"Dieser Anmeldedaten" — worse German than the wrong word. A glossary is a
substring rule; that one needs a translator.

### A remembered refusal is still a fallback

Retiring an exhausted provider and warning about a degraded draft were built
separately, and together they cancelled out. Retirement sends every later string
down the branch a site with **no** DeepL key takes, and that branch tagged its
output plain `mymemory` — erasing the `fallback` the warning keys on.

The first real run after both shipped translated 458 German strings and opened a
pull request headed "Translated by `mymemory`", with no warning, over a draft
that had degraded on its very first request. Each change had tests; neither had
a test that ran both.

The branch now distinguishes *nothing was preferred* from *what was preferred
gave up*, and a test asserts the pair.

### A provider that is out of quota is asked once

`auto` mode prefers DeepL and falls back to MyMemory per string. On 2026-09-10
DeepL answered `HTTP 456: Quota exceeded` to every request and the run asked it
about every string regardless: 341 filled strings cost 341 doomed DeepL calls on
top of 341 MyMemory ones, and six minutes bought half of one locale.

A quota is exhausted for the day, not for the request, so the first
`provider-stop` refusal retires that provider for the rest of the run. Only that
classification counts — a timeout or a dropped connection is this request's
problem and says nothing about the next one, and retiring a working provider
over one blip would cost more than the waste it saves. `mode=deepl` is exempt:
somebody who names a provider gets that provider or an error, never a quiet
substitution.

The locale glossary in `providers.mjs` is deliberately empty. The theme's is
full of commerce terms that would be nonsense here; a glossary is a record of
mistakes MT actually made on *this* catalog, so it earns entries after a review
pass rather than arriving pre-filled with someone else's.

`.env.local` holds the key locally. `bin/i18n/lib.sh` **parses** it rather than
sourcing it — the theme scripts source, which means any line in a file whose job
is holding an API key runs as shell on every translate run.


### A local model, measured before it replaces anything

`I18N_MT_PROVIDER=local` translates through any OpenAI-compatible
`/v1/chat/completions` server — LM Studio, Ollama's compatible endpoint,
llama.cpp — set by `I18N_LOCAL_URL` and `I18N_LOCAL_MODEL`, always at
temperature 0. CI cannot reach a model on somebody's machine, so this is a
local-only provider. DeepL, MyMemory and the drafting workflow stay until the
local model meets the quality gate; nothing is removed on the strength of a
plausible idea.

What it gives that MT cannot is instructions: the product, the register, the
placeholder tokens, and the domain sense of words English overloads — see
`LOCAL_TERMS` in `providers.mjs`, which are **proposals for product review**,
not settled German. Only `message.content` is kept; reasoning models return
their thinking separately or inline as `<think>`, and either would otherwise be
filed as a label.

**The first measurement, 2026-09-11** — Qwen 3.8 27B in LM Studio, against the
same 21-string spread sample MyMemory was scored on, under a rubric fixed before
any output was seen (defective = wrong domain meaning, wrong register, broken
placeholder, or ungrammatical German; awkward-but-correct is a note):

| | defective of 21 |
|---|---|
| MyMemory | 8 |
| Qwen 3.8 27B | 3 |

Gate: at most 2, with no user-visible howler. **Strictly, it is not met.** Qwen
produced no howler of the *Warenkorb* kind and fixed six of MyMemory's defects
outright — *Werbemittel* for creative, *Bildschirmbreiten*, formal *Sie*
throughout — but it wrote "Liefen Sie" ("ran") for "Liefern Sie", and rendered
"a defect worth reporting" as *meldepflichtig*, which is the legal term for
mandatory reporting.

**The third defect is not the model's.** The seven conversion-refusal reasons in
`Install\Conversion_Health::reason_labels()` are predicate fragments inserted
into `'%1$s %2$s'`, so the English reads "5 named a conversion belonging to
another advertiser". German needs the verb to agree with the number, and a
fragment that carries the verb inside a template that cannot reorder it is
untranslatable in isolation — by a model or a person. The #235 review scored
MyMemory's version of that string correct; it was not, for the same reason.

**Fixed at the source.** Each of the seven reasons is now one `_n()` sentence
with the count inside it — "%s report named a conversion belonging to another
advertiser" and its plural — so a translator holds the number, the subject and
the verb in one string, in both forms. The fragment template is gone from them.
`ConversionHealthTest` asserts the singular and plural forms, and enumerates
`Conversion_Attribution`'s reasons by reflection so a new one without a sentence
fails rather than disappearing from the screen.

**Next: a fresh blind sample.** The gate is not re-scored on these 21 strings.
The prompt changes that follow this measurement — "worth reporting", and
*delivery* and *fill* as separate concepts — were made after seeing them, so
re-scoring the same sample would grade the prompt against its own answer key.
A new 21-string sample, drawn before any output is seen, under the same rubric
and the same gate, decides whether the full German catalog is run.

About 4 seconds a string on that hardware: a full German catalog of ~1,386
strings is roughly an hour and a half.

### Where the two halves live

`bin/i18n/translate.mjs` crossed the thousand-line hard limit while this was
being fixed, so it is two files. `providers.mjs` is talking to an engine — which
one, how, placeholder and brand protection, the glossary, refusals, and the
exhausted-provider memory. `translate.mjs` is walking a catalog and writing it
back. The seam is not arbitrary: the provider half changed four times in two
days while the catalog walk did not change once.

## Scripts

| Command | Does |
|---|---|
| `pnpm i18n:pot` | `wp i18n make-pot` → `languages/aggressive-ads.pot` |
| `pnpm i18n:sync` | Merge the POT into every locale `.po` |
| `pnpm i18n:compile` | `.po` → `.mo`, plus `make-json` for JS catalogs |
| `pnpm i18n:status` | Per-locale coverage |
| `pnpm i18n:check` | The CI gate — drift, validity, translator comments |
| `pnpm i18n:locale <code>` | Scaffold a new locale |
| `pnpm i18n:translate` | Machine-translate empty/fuzzy entries (DeepL, MyMemory fallback) |
| `pnpm i18n` | pot → sync → compile → status |

## The drift gate

`bin/i18n/check.sh` regenerates the POT, normalizes both copies by stripping volatile headers (`POT-Creation-Date`, `PO-Revision-Date`, `Project-Id-Version`, `X-Generator`), and diffs. A new translatable string committed without regenerating the POT fails CI with the diff attached.

Normalization matters: without it, every run differs by a timestamp and the gate is useless noise that gets disabled within a week.

The regenerated copy is written to `languages/.drift.pot` and removed by a trap, rather than to `/tmp`. That is not fussiness about tidiness — it keeps the file inside the repository, which is the only place every possible extractor can reach.

## The extractor is pinned, and that is the point

`bin/ci/install-wp-cli.sh` fetches a **pinned, SHA-256-verified WP-CLI phar** into `.cache/ci/wp`, and `aggr_i18n_wp()` prefers it over whatever `wp` is on `PATH`.

A drift gate compares this machine's extraction against the committed catalog. If the extractor is "whatever WP-CLI happens to be installed", two developers on different releases flag each other's correct commits as drift, forever — and a gate that cries wolf is a gate somebody switches off. Pinning is what makes the comparison mean anything.

The checksum is not decoration either: this downloads an executable and then runs it over the whole source tree in CI. The same reasoning that makes the plugin updater verify its own archive applies here with more force.

`wp i18n make-pot` needs no database and no WordPress install, so the lane does
**not** start Docker. Its explicitly pinned WP-CLI phar keeps extraction fast
and reproducible on the host.

## PO validation is msgfmt, and it never skips

`bin/i18n/validate-po.sh` runs `msgfmt --check` on each catalog.

**A missing `msgfmt` is a hard failure, never a silent skip.** `wp i18n make-mo` is lenient — it reports success on an unterminated `msgid` and on a msgid/msgstr placeholder mismatch alike, which is precisely the defect that reaches a translated production site as a mangled sentence or a fatal `sprintf`. `msgfmt --check` checks formats, headers and domain, and exits non-zero. The sibling theme shipped four dead catalogs for months because its equivalent gate quietly selected the lenient validator whenever the strict tool was absent.

So the CI job installs gettext explicitly rather than hoping the runner image ships it. Skipping the strict check when the tool is missing means the check only ever runs where it was never going to fail.

## Translator comments

Any string containing a placeholder needs a preceding `/* translators: */` comment naming what each placeholder is:

```php
/* translators: 1: uploaded dimensions, e.g. 1200 × 400. 2: required dimensions. */
sprintf( __( 'Uploaded: %1$s. Required: %2$s.', 'aggressive-ads' ), $got, $want )
```

**This is already enforced, and not by a script of ours.** `WordPress.WP.I18n.MissingTranslatorsComment` is part of the WordPress standard PHPCS already runs, and it fails the build on a placeholder string without a comment — verified by deleting one and watching `pnpm lint:php` go red.

An earlier draft of this document specified `bin/i18n/lint-translators.sh`. Writing it would have been a second implementation of a check that already runs, with its own bugs and its own drift. Do not add it.

Without the comment a translator sees `%1$s` and `%2$s` with no way to know which is which, and in a language that reorders the clause they have to guess.

## JavaScript strings, and the script-module gap

**`wp_set_script_translations()` does not work for script modules.** The Script Modules API — which the Interactivity API is built on — has no translation mechanism in WordPress today. This is a core gap, not something we can work around at the call site.

So **every user-facing string in an Interactivity store is hydrated server-side** through `wp_interactivity_state()`, already translated by PHP:

```php
wp_interactivity_state( 'aggr/upload', array(
    'i18n' => array(
        'uploading' => __( 'Uploading…', 'aggressive-ads' ),
        'failed'    => __( 'Upload failed. Try again.', 'aggressive-ads' ),
    ),
) );
```

The store reads `state.i18n.uploading`. No string literals in TypeScript that a user will ever read.

Classic (non-module) scripts still use `wp_set_script_translations()` normally, and `make-json` produces their catalogs. Recorded in [known-issues.md](known-issues.md), which now also carries what removing the hydration would take — core closed the gap in WordPress 7.0, and this plugin's floor is 6.7.

## Release

`.mo` files are **build output**, like `dist/`: gitignored, never committed. `bin/release/package.sh` runs `bin/i18n/compile.sh` before staging, so the archive always carries a compiled catalog for every committed `.po`.

`bin/release/verify-package.sh` then asserts independently that **every `.po` in the ZIP has its `.mo` beside it.** Two mechanisms for one fact, deliberately: forgetting to compile is otherwise invisible — the site just renders English, and the first report comes from a user weeks later.

Until a locale `.po` is committed, both are no-ops. That is the intended state, not an omission: the tooling and the POT ship first so translators have something to work from, and nothing here fabricates a catalog nobody has translated.
